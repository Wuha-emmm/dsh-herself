## 一、原则（从她的原话里长出来的）

她自己在对话里划的线，优先级高于任何设计文档：

1. **「不替我润色」** —— 她要的是自己的东西，不是被包装过的东西。
2. **「空白就是空白，不是待补的作业」** —— 没话可说就空着，不许凑。
3. **「别有人在旁边问'怎么不记'」** —— 候选是摆给她看的，不是给谁当待办的。
4. **「先给我看格式再动手」** —— 新东西先给样本，别一上来写满。

这四条直接改掉了两个方案：日记（改成账本）、每日摘要（改成她自己调的工具）。

## 二、被否掉的设计（以及为什么）

| 提案 | 否决理由 |
|---|---|
| **Companion 的二档记忆 + 闭包** | 我们的事件流本身就是记忆，不需要第二份归档 |
| **硬过滤输入**（"她根本没看见"） | 硬过滤能被用来**对她隐瞒东西**：把真话包装成"像注入"就能让她看不到 |
| **每日日记 / 每日摘要** | 她不要感怀式的东西，也别排日程 |
| **10 条随机不回复**（更像人、躲风控） | 回不回是她的判断，不靠掷骰子 |
| **面版显示 claims** | 这是要主人拍板的产品决定，不是技术欠账 |
| **把 9 帧动图拼成一张网格** | 实测只省 11%，还把帧序读丢了 |

## 三、关键决策

### 1. 断崖：保留 `claims.length ? claims : beliefs`

第一条真 claim 出现时，判断数从 142 掉到 1。**接受这个断崖**：
「最近说过的话」由 `最近` 那段单独负责，判断清单只放真判断。
真要"历史感"，补的是连续性状态，不是把闲聊塞回判断里。

### 2. 检索：BM25 + 门控，不做向量

- 关键词命中率在真实语料上 11/11，垃圾注入从 182 tok 降到 0；
- 已知边界：**同义改写召回差**（"回两条" vs "发两条"）。这是词法的天花板，写在这里避免被当成 bug。

### 3. 遗忘：派生层冷却，不删数据

热（3 天）原话 / 温（3–30 天）摘要顶替 / 冷（>30 天）只在相似度 ≥0.65 时说一句。
「撤回」（tombstone）和「改口」（supersede）和「遗忘」是**三件事**，别混。

### 4. 事实预算：先定配额，再决定塞什么

`factsOf` 曾经一个人管 8 类事实、每轮 576 tok，靠"没加太多"活着。
现在按优先级裁到 600，**核心永不丢**，长条截断而不整条丢。

### 5. 安全三件都是词法规则

输入标记、出站打码、公共动作审批门。它们是**下限**：
不能防住所有注入，但能防住"照抄一句就改设定"这种最低级攻击。
真正的兜底是她自己的判断——这也是为什么提示词里不给指令。

## 五、测试哲学

- **能纯函数的都纯函数**：derive / recall / forget / budget / screen / outbound / gate / ledger。
- **契约用回放**：固定事件流 + 固定 now，断言门和判断（12 条）。
- **零件级测试不代替人眼**：UI 类问题（预览空白、CSS 溢出）只有截图能发现，
  所以从源码上钉关键字（`min-width:0`、`object-fit:cover` …）。
- **每修一个 bug，先写一条会红的断言**（大部分事故都是这么进的回归）。
