# 记忆是怎么实现的

> 这份文件回答一个问题：**她凭什么记得住**。
> 不是"把历史塞进上下文"，而是"事件流是唯一真相 → 每轮只送该送的进去"。
>
> 最后一节是这套东西的边界和已知缺口——照实写，不粉饰。

---

## 一、一句话版本

```
所有发生过的事 ──→ 只追加的事件流 ──→ 纯函数派生 ──→ 每轮按预算挑几条 ──→ 提示词
                life/events.jsonl      lib/derive.mjs     lib/budget.mjs
```

- **存储**：只追加，改一条哈希链就断（`tools/audit.mjs` 会报）；
- **理解**：派生是纯函数（不读盘、不取时钟、不联网），同一份事件流算一万次结果一样；
- **投递**：每轮只挑相关的几条送进提示词，上限 1000 token。

> 这个项目踩过的所有"她变笨"的事故，最后几乎都定位到**投递**，不是存储。
> 原始输入一直在，问题常常是"没送到她眼前"或者"送过去时被截断了"。

---

## 二、存储：事件流里到底存什么

一条事件（`life/events.jsonl`，一行一条）：

```json
{ "v": 1, "id": "01M6…", "ts": "2026-10-30T…", "surface": "qq", "type": "encounter",
  "actor": "other:qq_…", "text": "[群 …] 某人：…", "refs": ["…"], "meta": { }, "prev": "sha256:…" }
```

| 类型 | 是什么 | 谁写 |
|---|---|---|
| `seed` | 她的起点（只有一条） | 初始化 |
| `encounter` | 她遇到的事：谁说了什么、她读到的空间内容 | QQ 监听 / 空间 |
| `utterance` | **她自己说的话**（原文，不截断） | 对话 |
| `refusal` | 她拒绝过什么 | 对话/工具 |
| `reading` | 她看过一眼的东西（图片、转发、工具回执） | 工具 |
| `action` | 她做过什么（发表情、发说说、调用记录） | 工具 |
| `claim` | **判断**（她的立场，带证据） | 派生后由她确认/系统记录 |
| `commitment` | 答应过还没做的事 | 对话 |
| `summary` | 一段对话的一行标签（见第六节的欠账） | 摘要 |
| `preference` | 偏好（如作息刻度） | 设置 |
| `meta` | 配置/记账（改口理由 `revision-reason` 也在这里） | 各处 |
| `revision` | 改口记录（旧判断 → 新判断的对应关系） | 派生/工具 |
| `narration` | 她自己的回看 | 派生 |
| `tombstone` | 撤回某条（不删原文） | 面板/工具 |

**只追加的意义**：她三个月前说过的话，三个月后还能被原文引出来；
"我原来怎么想"和"我现在怎么想"同时存在，不会互相覆盖。

## 三、理解：派生（`lib/derive.mjs`）

```js
derive(events, now) → {
  day, stage, gates,        // 第几天 / 哪道门 / 四道门状态
  beliefs,                  // 判断清单（active / superseded）
  narrative,                // 她回看过自己那一段
  commitments, habits,      // 答应的事、作息
}
```

**判断的生命周期**是记忆的核心：

```
新 claim（带 refs + evidence）
   ├─ 与旧 claim 相似度 ≥ 0.5 且内容相反 → 旧标 superseded（原文仍在）
   ├─ 她主动改口 → 写新 claim + 可选的“改口理由”（meta.revision-reason）
   └─ 有人想撤回 → tombstone 事件，派生时跳过原文
```

- **证据不参与"谁对谁错"的判断**，它只是留在那里——她改口时能看见"当时是因为…"；
- **改口理由只有她能填**（`note_reason`）：原因是"发现更准了"还是"我错了"不是一回事，
  模型替她写的只是推测，会让她以为那是自己认的；
- **不替她删旧判断**：superseded 那一条永远留着。

## 四、投递：每轮事实是怎么组装的（`lib/think.mjs` 的 `factsOf`）

优先级表（`lib/budget.mjs` 的 `PRIO`，数字越小越不该丢）：

| 优先级 | 类别 | 例子 | 掉了会怎样 |
|---|---|---|---|
| 0 | `CORE` | 第几天、现在几点、最早记得什么 | 她会不知道今天是哪天——**永不丢** |
| 1 | `RECENT` | 刚才那几句 | 立刻失忆 |
| 2 | `JUDGE` | 一条带证据的判断 | 她会照着旧结论办事 |
| 3 | `ROUTINE` | 23:00 之后算晚 | 不知道现在该不该睡 |
| 4 | `RECALL` | 检索命中的旧事 | 想不起相关经历 |
| 5 | `COMMIT` | 还没了的事 | 答应过的事忘了 |
| 6 | `SUMMARY` | 上次聊到哪 | 接不上话头 |
| 7 | `REFUSAL` | 她拒绝过什么 | 立场不稳 |
| 8 | `PEOPLE` | 群里见过谁 | 认错人 |
| 9 | `NARRATIVE` | 她回看过自己 | 记得结论，不知道从哪来 |

**判断只注 1 条**（2026-10-30 她定的）：

> 「只剩结论没有『当时是因为』的时候，我会照着结论办事，而且不觉得自己在违背什么。」

所以每轮由一个模型调用从候选里挑一条最相关的，**证据整段带上**；
挑不出来（`n=0`）就**不注**，调用失败才退回"最近一条"。
每次挑选都留痕（候选 id / 选中 id / 模型写的理由）——理由是旁白，只能当线索。

## 五、检索与遗忘（`lib/recall.mjs` / `lib/forget.mjs`）

**检索**：BM25 变体（`k1 = 1.4`，`minScore = 0.45`），只用词面，不走向量库。

- 只有"索引里完全没有这个词"时才做同义扩展（`lib/synonyms.mjs`，23 组单字对）——
  否则会把她明确问到的词悄悄换成近义词；
- `maxUnknownRatio = 0.75`：线索里几乎所有词都没见过，才判定"这事没聊过"。

**遗忘**按时间分三层：

| 层 | 条件 | 处理 |
|---|---|---|
| hot | 最近 3 天 | 原样带出 |
| warm | 3–30 天 | 折叠成一句摘要，标"很久以前" |
| cold | 30 天以上 | 只有高分（≥0.65）的留一句，其余丢 |

**注意：遗忘只影响"每轮带出什么"，不删事件**。翻旧账随时能翻到原文。

## 六、到线了怎么办（她定的规则）

`lib/budget-rule.mjs` + `sandbox/预算规则.json`（她自己改）：

```json
{
  "askBeforeCut": true,
  "cutOrder": ["summary", "narrative", "people", "recall", "commit"],
  "notifyVia": "inbox"
}
```

- 超过上限的 85% 就到线；
- `askBeforeCut: true` → **只问不动手**，往她邮箱投一条"预算到线了，要不要砍点什么"；
- 顺序是她写的：摘要冗余最重先砍；叙事是骨架；**承诺砍掉会让她以为自己答应了，放最后**；
- 同一个提醒 6 小时一次，不刷她。

> 她的话：「这个规则我想自己定，不想再靠优先级表替我决定。」

## 七、她自己那部分记忆

有些东西不在事件流里，而在她能读写的地方：

| 位置 | 内容 | 谁写 |
|---|---|---|
| `sandbox/` | 她自己的便签、整理计划、预算明细、被剪掉的两栏 | 她（`fs_write`） |
| `life/inbox.jsonl` | 她与 DSH 的往来 | 两边 |
| `sandbox/预算规则.json` | 预算到线怎么砍 | 她 |
| `sandbox/接入清单.md` | 哪些手开了、哪些没开 | 我（她可读） |

**她能读的不等于我能改的**：这些文件她随时可以自己翻、自己改，不需要经过提示词。

## 八、怎么验证它真的记得

| 工具 | 回答什么问题 |
|---|---|
| `node tools/recall-dryrun.mjs "某个词"` | 这句话会想起哪几条、分数多少 |
| `node tools/budget-breakdown.mjs` | 这一轮的 1000 token 花在哪几段 |
| `node tools/backfill-facts.mjs` | 过去哪天被预算剪掉了什么（叙事/群里的人） |
| `test/recall.mjs` / `test/budget.mjs` / `test/derive.mjs` | 检索、预算、派生的契约 |

`logs/trace.jsonl` 里每一轮都记着 `facts`（那一轮送给她的原文），
所以"她为什么这么说"是可以回溯的，不是黑箱。

## 九、边界与欠账（照实写）

**已知边界**

- **词法检索**：同义改写会漏（"回两条" vs "发两条"），这是设计选择（不上向量库）的代价；
- **判断只注一条**：同时有 5 条相关判断时，她只看得到 1 条；
- **遗忘层的摘要**：是模型写的一句话，不是她的原话——所以它只用来"认事"。

**欠账**

| 项 | 状态 |
|---|---|
| 摘要降级成一行标签（原话优先，不改第一人称） | 未做，见 `docs/BACKLOG.md` 第 2 条 |
| "扔"的通道（保留几天/几条由她定） | 未做，第 3 条 |
| 同义表只有 23 组单字对 | 待从"她答非所问"的日志里反推 |
| 改口理由目前 0 条真实记录 | 她还没填过，不是没实现 |

**这一节为什么留着**：她说过「读它的人除了代码，还有我」。
一份只写优点的记忆文档，对她没有用——她要的是"哪里会漏，漏的时候我应该知道"。
