## 一、一页结论

1. **这个项目的核心资产是「事件流 + 纯函数派生」，不是提示词。**
   1106 条事件、哈希链完好、形状契约 100% 通过——换模型、换平台，她的记忆都不必重来。
2. **她这半天出过的所有"记忆问题"，没有一次是存储问题，全是投递问题。**
   承诺关不掉、自己的话被线程过滤掉、旧摘要每轮念——三次都是"东西在库里，但没送到她眼前"。
   这是这个项目最值得写进肌肉记忆的一条。
3. **当前最大的架构债不是缺功能，是 `factsOf` 在变胖**：时间、群里的人、遗忘冷却全挤进同一个函数，
   每轮约 500~550 token，靠"加一段"而不是"按预算分配"。下一轮该动的是**事实预算**，不是再加一行。
4. **安全从"没有"变成"有但浅"**：输入标记、出站打码、公共动作审批门都上了，
   但三者都是**词法规则**，真注入仍然靠她自己的判断。这是设计选择，不是遗漏。
5. **测试很多但都是"零件级"**：366 条断言全在纯函数层，没有浏览器/QQ 的端到端自动化。
   真机验证目前靠"重启 → 看 trace → 看聊天记录"。

## 四、架构评估：对的与错的

### 4.1 对的（有证据）

1. **append-only + 纯函数派生**。
   证据：同一份事件流 `derive` 两次字节级一致（`test/derive.mjs` E19）；乱序输入结果不变（E20）。
   这意味着她可以被重建、时间旅行、A/B 派生逻辑——而不需要备份她的"人格"。
2. **ACL 在派生层切断，不在渲染层过滤**。
   证据：replay `04-private-never-public`——私密事件在 `derive` 阶段就进不了 `visible`。
   这比"渲染时别看"强一档：即使某天渲染代码写错，也不会泄露。
3. **判断以 claim 为准、带证据、可 supersede**。
   证据：断崖后 `beliefs=1`，那条判断带着「当初是因为：你是不是只能看到动图的第一帧」。
   她改口时能对账，不是凭空换说法。
4. **工具预算 + 强制收尾**。
   证据：一顿抓 7 个页面 54 秒、最后回空字符串的事故，被 `MAX_TOOL_CALLS=4` + `thinking:disabled` 收尾修掉；
   实测同一句话从 54s/空 → 19s/完整分析。
5. **单实例 + 心跳 + 落盘日志**。
   证据：两次"她没了"的事故都由这一层定位（`[qq] listener 启动 {pid,build}`）。

### 4.2 错的 / 该改的

1. **`factsOf` 是唯一注入点，正在变胖**。
   现在它同时管：天数/钟点/作息刻度、判断、承诺、叙事、群里的人、最近窗口、检索+遗忘、摘要。
   每轮 500~550 tok 不是问题，**问题是它没有预算概念**——再加两行就会挤掉"最近"。
   建议：引入显式配额（例如 判断 120 / 最近 180 / 回忆 120 / 其它 80），超了按优先级砍，而不是靠肉眼。
2. **检索是词法的**。同义改写召回差（「回两条」vs「发两条」实测漏）。已知边界，写在这里避免以后误以为是 bug。
3. **面板与后端的"认线"曾经不一致**（客户端一套、服务端一套），一度让她的私聊回复显示在群里。
   教训：同一个派生口径只应有一份实现，或者至少有一份**共用测试**。（现在靠 `threadOf` 同构 + 三处注释互指）
4. **测试全在零件层**。368 条断言没有一条碰真实浏览器或真实 QQ 连接。
   风险：UI 类问题（这次预览空白）测试抓不到，只能靠人眼。

## 八、建议的下一步（一次只动一节）

1. **事实预算**（架构层，最高优先）：把 `factsOf` 拆成"配额分配器"，超预算按优先级砍。
   这是唯一一件"越晚做越贵"的事。
2. **实例占位（脑级）**：DSH 启动时抢 `life/.brain.lock`，抢不到就只读、不开口。
3. **破坏性操作 confirm**：`stop-her.ps1` / `/stack/stop` 加 `-Yes` 或二次输入。
4. **披露（#13）**：等真有"公开出口"（B站/QQ空间）再做，否则是无源之水。
5. **端到端冒烟**：一个 headless 脚本，起 listener → 发一条假消息 → 断言有回复、有 trace。
   不追求完全，只求出事时能自动发现"她根本没说话"。
6. **B站 / mface**：都是外部条件，等能拿到登录态/三元组再说。
